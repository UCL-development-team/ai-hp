## 2. `.claude.json` の重複キー修正

**User:** 重複キーの修正をお願いします。

**Assistant:**
バックアップを取ってから修正した。

- 対象は `projects` 配下の6キー。うち同一ディレクトリを指すものが4つ（UNC・`R:\`・`R:/`・`r:/`）
- `R:/...` と `r:/...` の**中身が完全に同一**であることを比較して確認 → どちらを消しても情報を失わない
- 小文字の `r:/...` を残して `R:/...` を削除。VSCode 拡張から起動したセッションの cwd が `r:` 表記であり、そちらが実際に書き込まれているキーだったため
- バックアップ：`C:\Users\takah\.claude.json.bak-20260810`

**あわせて前回ログの記述を訂正した。**「JSON として不正」ではなかった。`JSON.parse` は修正前から通っており、JSON 仕様上 `R:/` と `r:/` は大小の違う別キーなので重複ではない。落ちていたのは**プロパティ名を大文字小文字を区別せず扱う PowerShell の `ConvertFrom-Json` だけ**だった。実害も限定的で、Claude Code は cwd 文字列で完全一致引きするため `R:/` エントリは参照されない残骸だった。

修正後、PowerShell の `ConvertFrom-Json` が通ることを確認。

## 5. 原因の確定 — マップドライブ `R:` が realpath で UNC に化ける

**Assistant:**
履歴ディレクトリ名を計算する経路を末端まで読んだ。

```js
async function ble(e){ try{ return nu(await ao.realpath(e)) } catch { return nu(e) } }
function yF(e){ return e.replace(/[^a-zA-Z0-9]/g,"-") }   // ディレクトリ名の変換
function yle(e){ return ss.join(Uh(), $h(e)) }             // ~/.claude/projects/<変換後>
```

`listSessions` → `tde` → `RAt` の入口が `await ble(this.cwd)`。ここで**非同期版の realpath** が使われているのが致命的だった。実測値：

| 呼び出し | `r:\__Source_github_ucl\ai-hp` の解決結果 |
| --- | --- |
| `fs.realpathSync`（JS実装） | `r:\__Source_github_ucl\ai-hp` ← そのまま |
| `fs.realpathSync.native` | `\\Synology\Data\__Source_github_ucl\ai-hp` |
| `fs.promises.realpath`（= 拡張が使う `ao.realpath`） | `\\Synology\Data\__Source_github_ucl\ai-hp` |
| 参考 `C:\Users\takah` | `C:\Users\takah`（マップドライブ限定の問題） |

**書き手（CLI）はドライブレターのまま、読み手（拡張）は UNC 解決後。同じフォルダを別名で計算していた。**

- 拡張が探す名前：`--Synology-Data---Source-github-ucl-ai-hp`（存在しない）
- 実際の履歴：`R----Source-github-ucl-ai-hp`（20ファイル）

そこから先はドミノ。

1. `Db()` が `readdir` に失敗（ENOENT）→ 候補リストが空
2. 救済処理（各 `.jsonl` の `cwd`/`relocatedCwd` を読んで移転先を突き合わせる `xle`）は**名前が200文字を超えて切り詰められた時だけ**通る経路。今回は41文字なので即座に空を返す
3. ホストは0件を返す
4. webview に残るのは、webview がローカルに作った進行中セッション1件だけ → 「表示中の1件しか出ない」

`.claude.json` に `\\Synology\Data\...` キーがあったのも、この UNC 解決を通った経路が書いたものだった。

**前回の切り分けが外した箇所も特定できた。**「`realpath` がマップドライブを UNC に化かす → シロ」という判定が誤りだった。同期版 `fs.realpathSync` で試したため `r:` がそのまま返りシロに見えたが、拡張が使うのは非同期版で、そちらは UNC を返す。

`Get-Item` で `Mode: d----l` / `LinkType: Junction` / `Target` を確認。

この回避策の性質：

| 項目 | 影響 |
| --- | --- |
| CLI の書き込み先 | 変わらない（従来どおり `R----...` へ書く） |
| ファイルの二重化 | なし（同一実体への別名。`AAt` が sessionId で重複排除もする） |

| 将来 | 拡張側が修正されても、残っていて害はない |

パネルを開き直すと webview が `list_sessions_request` を投げ直すため、VSCode の再起動は不要。最終的な件数の確認はユーザー側の目視待ちとした。
