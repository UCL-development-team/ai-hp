## 2. タイムライン図の追加修正（縦積み時の画像の伸び）

**User:** 縦積み時、FOCUS AREA 01 の図だけおかしくなる。他の2つの図は崩れない。

**Assistant:**
原因は **flex の主軸の向き**だった。

FOCUS AREA 01 だけが「図の右にタグを縦に並べる」ため `.area-row`（flex コンテナ）を使っている。縦積みで `flex-direction:column` に切り替わると主軸が縦になり、横並び用に指定していた `flex:0 1 520px` の **520px が「幅」ではなく「高さ」の基準として解釈**され、`align-items:stretch` で幅も枠いっぱいに広がるため画像が縦に伸びていた。FOCUS AREA 02 と拡張ノートは素の `.viz` だけが効くので無傷だった。

メディアクエリ内に1行追加して解決。

```css
.timeline .area-row .viz{flex:none; width:100%; max-width:520px}
```

**`flex-direction` を切り替えるメディアクエリでは `flex-basis` も併せて見直す必要がある**、というのが今回の落とし穴。

## 4. モバイルのサブヘッダー

**User:** 添付画像のように、モバイル時は1段目にロゴ・2段目にナビリンクの2段組みにしてほしい。（以降、文字サイズと余白について複数回の指示）

**Assistant:**
デザインシステムは md でナビリンクを `display:none` にするが、このページのサブヘッダーは右にCTAボタンを持たないためロゴだけが残ってしまう。折り返して2段目に出す形に変更した。

途中、**「2段になると高さが可変になるので sticky をやめる」と提案したが、ユーザーから「高さが変わるのが問題なら、高さを変えなければよい。それはデザインの問題」と指摘を受けて撤回**。文字を小さくして高さを固定する方針に切り替えた。

### sticky の多段について確認したこと

`position:sticky` 自体に高さ指定は不要。問題は**2つ目の sticky**（案件カタログの目次 `.cat-nav`）で、**CSSには「1つ前の sticky の下に付く」という書き方が存在しない**ため、`top` に渡す数値を人間が計算する必要がある。だから上のサブヘッダーの高さが確定していなければならない。

「多段 sticky」と呼ばれるものは2種類あり、どちらも下に積む機能ではない。

1. **セクションごとの sticky ヘッダー** — 全部 `top:0`。sticky は自分の包含ブロックからはみ出せないため、親が画面から出るときに一緒に押し出され、入れ替わりで次が同じ位置に座る（積まれてはいない）
2. **それぞれの `top` を手で指定** — 同時に見せたい場合はこれしかない。テーブルのヘッダー行を2段固定するときも同じ

なお `@container scroll-state(stuck: top)` は「張り付いた状態で見た目を変える」ためのもので、位置の計算はしない。

### 最終形（820px以下）

| | 値 |
|---|---|
| 1段目「AI Innovation 部」 | 13px / 行間1.4 / 左上寄せ |
| 2段目 ナビリンク | `clamp(11px, 3.15vw, 14px)` / 行間1.5 / 右寄せ |
| 文字間隔 | `clamp(8px, 2.2vw, 14px)` |
| 帯の高さ | `min-height:66px`（幅によらず一定） |

**固定サイズをやめた理由:** 5つのラベルは合計23文字ぶんの幅を要求する（「AIを搭載するシステム」だけで4割強）。固定サイズだと、大きくすれば狭い端末で折り返して高さが変わり、折り返さない大きさにすると広い端末で小さすぎる。`clamp` で上限・下限を決めて間を伸縮させることで、**どの幅でも「1行に収まる範囲で最大」**になる。上限14pxは、その下のカテゴリ目次より小さく見えない大きさとして決めた（主ナビが従ナビより小さく見える階層の逆転が「違和感」の正体だった）。

`height` ではなく `min-height` にしてあるため、想定より狭い端末で折り返しても文字は切れず帯が伸びるだけで済む。

## 5. この状態での再レビュー

**User:** この状態で再レビューしてほしい。

**Assistant:**

### 新しく書いた部分（モバイルサブヘッダー）の指摘

**1. アンカーの着地位置が、モバイルで足りていないはず**

`.cat-group` の着地オフセット `calc(var(--sticky-top) + 76px)` は全幅共通だが、この `76px` はデスクトップの目次（1段）に合わせた値。モバイルでは目次が2〜3段に折り返す。

| | sticky合計 | 確保している値 |
|---|---|---|
| デスクトップ | 52 + 約47 = 99px | 128px ✓ |
| モバイル | 66 + 約82〜117px = **148〜183px** | 142px ✗ |

目次のリンクを押すと分類の見出しが目次の下に潜る可能性がある。md ブロックに1行足せば済む。

```css
@media(max-width:820px){ .cat-group{scroll-margin-top:calc(var(--sticky-top) + 120px)} }
```

**2. タップ領域が24px弱** — ナビリンクは 14px × 行間1.5 = 21px 高。WCAG 2.2 の最小タップ領域（24×24）をわずかに下回る。`padding:2px 0` で満たせるが、帯の高さ（66px）の再計算が要る。

**3. モバイルで画面上部の固定領域が大きい** — カタログ閲覧中は 本体ヘッダー＋サブヘッダー66px＋目次82〜117px が固定表示。640pxの画面では2〜3割を占める。

**4. 既知の限界（CSSコメントに記載済み）** — 幅336px程度を下回るとリンクが折り返し、帯が伸びて目次の位置が数十pxずれる。`min-height` なので文字は切れない。対象端末が iPhone SE 第1世代クラスのため実害は小さいと判断。

### 未着手のまま残っている項目（判断待ち）

1. **「成果で語る」×「SES」の矛盾**（`index.html:482` と `:74`）— 投影して順に説明すると流れの中で露出する
2. **FOCUS AREA 01 の体制図が、横並び時だけ小さい**（約380px / FOCUS AREA 02 は520px）— 縦積みは揃ったので横並びだけ不揃い
3. **コントラスト不足2か所** — 図版の `PAST`/`RECENT` が約3.5:1、フッターのコピーライトが約4.2:1（基準4.5:1）。前者は投影するとほぼ飛ぶ
4. **投影で読ませない情報の線引きを `index.md` に明記**
5. **`--host-header-height` が画面幅に追従しない** — 本体ヘッダーがモバイルで低くなる作りなら、差し込み時に md でも値を出し分ける必要がある
