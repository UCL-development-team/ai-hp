# チャット履歴ログ — チャット履歴が表示されない問題の調査

このファイルは Claude Code とのチャットのやり取りを記録したものです。
VSCode 拡張の履歴パネルに過去の会話が出てこない問題について、原因の切り分け手順と結論を残す目的で保存しています。

---

## 1. 問題の相談

**User:** チャットの履歴の表示機能があるはずだが、過去の履歴が全然表示されない。なぜか。

**Assistant:**
まず履歴の保存場所を確認した。

- `C:\Users\takah\.claude\projects\` 配下を調査
- このリポジトリ用のディレクトリ `R----Source-github-ucl-ai-hp` に **17セッション分（8/5〜8/10、計約30MB）** の `.jsonl` トランスクリプトが存在
- つまり **履歴ファイル自体は消えていない**

この時点で見つけた異常として、`C:\Users\takah\.claude.json` の `projects` に同じフォルダが複数の表記で登録されていた。

| 登録されているパス表記 |
| --- |
| `\\Synology\Data\__Source_github_ucl\ai-hp` |
| `R:\__Source_github_ucl\ai-hp` |
| `R:/__Source_github_ucl/ai-hp` |
| `r:/__Source_github_ucl/ai-hp` |

`R:` はNAS（`\\Synology\Data`）のマップドライブ。`R:/...` と `r:/...` が**重複キー**として同時に存在しており、JSON として不正な状態（PowerShell の `ConvertFrom-Json` が読めない）。

トランスクリプト側の `cwd` も割れていた。

- 8/5〜8/6 の5件 → `R:\__Source_github_ucl\ai-hp`（大文字）
- 8/7〜8/10 の12件 → `r:\__Source_github_ucl\ai-hp`（小文字）

ただしこれだけでは「全然表示されない」の説明にはならないため、どこで見ているのか・何件表示されているのかを確認した。

---

## 2. 症状の特定と原因の切り分け

**User:** VSCode 拡張の履歴パネル。表示中のものだけの1件しか出ていない。

**Assistant:**
拡張の実体（`C:\Users\takah\.vscode-insiders\extensions\anthropic.claude-code-2.1.224-win32-x64`）がディスク上にあるため、履歴一覧の実装を直接読んで検証した。

一覧生成のチェーンは `listSessions` → `Aue` → `ZOt` → `Qce`（`Wce` / `_Ot` / `Jce`）。この判定ロジックを Node で再実装し、実際の17ファイルに対して実行した。

**結果：17件すべてが「表示すべき」と判定され、タイトルまで正しく取得できた。**

```
021ddc9c  entry=claude-vscode  aiTitle=Y lastPrompt=Y => KEEP "部のホームページを作成"
ce4af7cf  entry=claude-vscode  aiTitle=Y lastPrompt=Y => KEEP "draw.ioタイムラインをインフォグラフィック化"
64c2d2c7  entry=claude-desktop aiTitle=Y lastPrompt=Y => KEEP "黒背景対応のロゴデザインを追加"
...（全17件 KEEP）
```

除外理由になりうる関門を1つずつ潰した結果が以下。

| 疑ったもの | 結果 |
| --- | --- |
| `R:` / `r:` のドライブレター不一致でプロジェクトディレクトリを見失う | **シロ**。NTFS は大小同一視。小文字パスで `readdirSync` して19件返った |
| SDK 経由セッションの除外（`includeProgrammatic:false`） | **シロ**。除外対象は `sdk-cli`/`sdk-ts`/`sdk-py` のみ。実データは `claude-vscode`(12件)・`claude-desktop`(5件) |
| タイトル/要約が無く `Jce` が null を返す | **シロ**。全件に `aiTitle` と `lastPrompt` がある |
| worktree の除外 | **シロ**。非worktreeパスでは `isCurrentWorkspace` は常に true |
| UIで非表示にした履歴（`hiddenSessionIds`） | **シロ**。VSCode の globalState にキー自体が存在しない |
| `realpath` がマップドライブを UNC に化かす | **シロ**。Node は `r:` を `r:` のまま返した |

つまり **保存データもリストアップのロジックも正常** で、原因は稼働中のクライアント側にある。

---

## 3. 結論と対処

**Assistant:**
残った唯一の具体的な異常は、**拡張ホストが3日間リロードされておらず古いバージョンで動き続けていること**。

- インストール済み: `2.1.224`（8/7）、`2.1.225`（8/8）、`2.1.226`（8/8）の3世代が同居
- `~/.claude/ide/37436.lock` が **8/7 14:52** のまま
- 8/8〜8/10 のトランスクリプトの `version` フィールドが全部 `2.1.224`

稼働中の VSCode Insiders の下で拡張が2回入れ替わり、ホストだけ 2.1.224 に取り残されている状態。履歴パネルは webview（`webview/index.js`）とホストの `list_sessions_request` のやり取りで描画されるため、この世代ズレでリクエストが通っていないという筋が最も濃厚。データもロジックも正常なのにパネルが空、という症状に合致する。

案内した対処手順：

| 手順 | 内容 | 目的 |
| --- | --- | --- |
| 1 | VSCode Insiders を完全終了して再起動（または `Developer: Reload Window`） | ホストに 2.1.226 を読み込ませる |
| 2 | `Claude Code: Show Logs` で `list_sessions` 周りのエラーを確認 | 直らない場合、拡張側バグとして確定させる |
| 3 | ターミナルで `claude --resume` | データ側の生存確認（17件のピッカーが出れば「保存は無事・表示だけ壊れている」が確定） |

あわせて、履歴パネルの原因ではないが実害のある別件として、`C:\Users\takah\.claude.json` の `projects` にある `R:/...` と `r:/...` の重複キー（プロジェクト単位の設定が片方しか効かない）を報告し、修正するかを確認した。グローバル設定のため指示待ちとした。

## 調査に使った主な確認コマンド

| 目的 | 内容 |
| --- | --- |
| 履歴ファイルの存在確認 | `~/.claude/projects/` 配下の `.jsonl` を一覧 |
| セッションの `cwd` 確認 | 各 `.jsonl` から `"cwd"` を抽出して比較 |
| `entrypoint` 確認 | 各 `.jsonl` の先頭64KBから `"entrypoint"` を抽出 |
| 拡張の判定ロジック検証 | `extension.js` から `Wce`/`_Ot`/`Jce`/`Ob`/`Nh` を読み出し、Node で再実装して実データに適用 |
| 非表示履歴の確認 | `%APPDATA%\Code - Insiders\User\globalStorage\state.vscdb` を複製して `hiddenSessionIds` を検索 |
| 稼働バージョン確認 | 拡張フォルダの世代と `.jsonl` の `"version"` フィールドを突き合わせ |
