## 1. HTML部品を1つだけ作って複数箇所に表示できるか

**User:** このような HTML の1部分を1つだけ作成して、同じページに複数表示させることは可能か。ただし React などを使った SPA アプリ化はしない前提で。

**Assistant:**
「可能」と回答したうえで、ビルド工程を持たない本リポジトリ（プレーン HTML/CSS、GitHub Pages 配信）に適用できる手段を3つ提示した。

事前に確認した対象:
- `docs/plan-5/` の構成と現在の未コミット差分（`#talent`「AI人材支援」セクションの追加。`.card` ブロックが3枚並ぶ形）
- `docs/plan-5/design-system/components.js`（既存の挙動用 JS。現状は Modal の開閉のみ、light/dark 共用）

提示した手段:

1. **Custom Element（Web Components）— 推奨**
   - `components.js` に `customElements.define('ai-card', …)` を1つ書き、HTML 側は `<ai-card n="01" tone="c4" title="…">本文</ai-card>` を並べるだけにする案。実際の `.card` マークアップに合わせたコード例を提示。
   - **Shadow DOM を使わず light DOM に書き出す**のがポイント。既存の `tokens.css` / `components.css` がそのまま効く。
   - 配色・寸法を持たないため、`components.js` の既存方針どおり light/dark 共用のままにできる。

2. **`<template>` + クローン**
   - 中身も含めて完全に同一のブロックを N 個置く場合の最小解。`data-tpl` 属性を置いたプレースホルダーを `template.content.cloneNode(true)` で置換するコード例を提示。

3. **`<iframe>` — 非推奨**
   - 高さの自動調整・スタイル継承・SEO がすべて面倒になる。`SDD-Kit` のモーダル内表示のような用途に限るべき。

あわせて、マーケティング用ホームページとしての判断材料を提示:

| 論点 | 影響 |
|---|---|
| SEO | Google はレンダリングするので基本は拾われるが、静的 HTML より確実性は落ちる |
| JS 無効 / エラー時 | セクションが丸ごと消える（ベタ書きなら必ず表示される） |
| 表示のちらつき | 描画後に差し込まれるためレイアウトシフトが起きうる |

結論として、**HTML ソースに実物が残る保証が欲しいならベタ書き（現状のコピペ）が一番堅い**、逆に同じブロックが4〜5個並んで修正漏れのほうがリスクなら Custom Element が明確に効く、という整理を伝えた。

そのうえで、対象となる HTML 断片（IDE で開かれていた Untitled-1 の内容）と、同じページに何個並べる想定かを確認中。実装には未着手。
